# 分段看视频

让机器人「按段看完」一个本地视频：每一段做分镜抽帧、拼成九宫格，配上这一段的台词（优先字幕），再交给视觉模型写一段观后感，逐段推送，最后给整片总结，并把看过的内容写进长期记忆。

支持的输入：

- 把视频丢进 `watch_dir`（默认丢到插件 `data/inbox`），在 QQ 里发 `/kv 文件名`；
- 直接把视频文件发给机器人（QQ 私聊）。

不限制时长——一小时、三小时都可以，按段滚动处理。

## 依赖

- `ffmpeg.exe` / `ffprobe.exe`：填 `ffmpeg_path` / `ffprobe_path`，或放进数据目录 `bin`、系统 PATH。
- Python 包：`pip install -r requirements.txt`（`funasr-onnx`、`onnxruntime`、`rapidocr-onnxruntime`）。
- 语音转写（可选兜底）：`asr_model_dir` 留空时，首次运行会自动把 SenseVoice ONNX 模型（约 240MB）下载到插件 `data/models/sensevoice`；也可以指向已有的模型目录。没配模型时只看画面与字幕，不影响主流程。
- OCR（可选，看硬字幕用）：`rapidocr-onnxruntime` 自带轻量模型，不需要额外下载。
- 一个支持图片输入的对话 Provider（用于读九宫格）。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/kv 文件名 [段数]` | 开始看视频，可选只看前 N 段 |
| `/kv zoom 段 格` | 把某一段的某一格再细分看（例如 `/kv zoom 3 5`） |
| `/kv status` | 看当前进度 |
| `/kv stop` | 停下当前任务 |
| `/kv list` | 列出可看的视频 |
| `/kv ocr on|off` | 开/关画面硬字幕 OCR（关掉就只读字幕轨或走语音） |
| `/kv chapters` | 列章节目录（时间 + 这一段讲什么） |
| `/kv jump 09:00` / `/kv jump 反转` | 按时间或关键词跳到某一段回看 |
| `/kv ask 这视频讲了什么` | 基于已看的段落回答问题 |

`zoom`、`chapters`、`jump`、`ask` 依赖缓存里的分段记录，所以要先 `/kv` 看过那个视频。

## 工作方式

1. `ffprobe` 取时长；
2. 每 `segment_seconds` 秒为一个窗口，窗口内用场景检测找切点；把窗口等分成 `frames_per_segment` 份，每份取「最长镜头的中间帧」，既有时间覆盖又避开转场糊帧；快剪片（平均镜头短于 2 秒）默认再取前后两帧左右拼成「双联帧」；格数不够密时（每格跨度超过 8 秒）会自动补格，并在开头告诉你「抽查间隔约 N 秒，即最大盲区」；
3. 每格取一帧，按格数自动排成 2/3/4/5 列拼图（带编号和时间轴）；
4. 取这一段的台词：
   - 有内嵌字幕轨 → 直接读字幕；
   - 没有 → OCR 画面底部字幕带：按原分辨率裁出字幕带，窄带再放大 2×，逐帧优先取中文字幕行，连续重复行自动去重；
   - 都没有 → 抽音频交给 SenseVoice 转写；转写前先做音量预检（整段静音或纯 BGM 直接跳过，标为「无文本」）；转写结果如果过短、或分块结果反复相同，判为幻觉丢弃，不会写进记忆；
5. 拼图 + 台词一起给视觉模型，写「这一段发生了什么」；
6. 逐段推送图和摘要，最后用所有分段摘要合成整片总结与章节目录；
7. 按 `memory_write_mode` 把每段 / 整片写进「我会牢牢记住你」的长期记忆（`shared_watch`）。

二级特写：每段结束后，如果开了 `auto_zoom`，会挑切点最多的一格再展开成一张更细的九宫格；也可以随时用 `/kv zoom` 手动展开。

## 配置

面板「已安装 → 分段看视频 → 参数设置」里可以直接改，保存后下一段生效：

- `segment_seconds`：每段时长（默认 300）
- `frames_per_segment`：每段格数（默认 9）
- `scene_threshold`：切镜灵敏度（0.2 更碎，0.5 更粗）
- `double_frame`：快剪双联帧
- `zoom_enable` / `auto_zoom` / `zoom_frames`：特写开关与格数
- `subtitle_enable`：优先读内嵌字幕轨（默认开，几乎零成本）
- `ocr_enable`：OCR 画面硬字幕（默认开；约 1 秒/帧，长片会明显变慢，关掉就走语音）
- `ocr_fps` / `ocr_band`：OCR 取样频率（默认 0.4）与字幕带高度（默认 0.24）
- `asr_enable` / `asr_language`：语音转写开关与语种（`auto`/`zh`/`ja`/`en`/`ko`/`yue`）
- `asr_model_dir` / `asr_auto_download`：模型目录（留空为插件内目录）与是否自动下载
- `memory_write` / `memory_write_mode`：是否写入长期记忆，`both`/`segment`/`final`
- `push_progress` / `push_segment_detail`：是否逐段推送、每段是否带图
- `watch_dir`：视频文件夹（留空时用插件 `data/inbox`）
- `max_segments_per_run`：单次最多看几段，0 为不限

## 缓存与断点

分段结果存在 AstrBot 的 `data/plugin_data/astrbot_plugin_video_storyboard/cache/<视频指纹>/` 下：每格的帧、拼图、音频与 `log.json`（每段摘要、转写、文本来源、特写记录、章节）。

同一个视频再发 `/kv`，会复用已完成的分段，从断点继续；要重跑就先删掉对应缓存目录。

## 成本

按 5 分钟 9 格算：一小时约 12 段、12 张图；每段一次视觉调用。转写走字幕时几乎零成本，走 OCR 时每段多几十秒 CPU（1.07 秒/帧，0.4 fps 取样）。本机 29 分钟的视频大约 8–9 分钟跑完。

把 `frames_per_segment` 调大、`segment_seconds` 调小都会提高密度，也等比增加 token 和耗时。

## 注意

- 视觉模型看不到视频流，它看到的是拼图和台词文本；
- OCR 依赖画面里有清晰的硬字幕；字体太小或描边复杂时会有错字，`ocr_band` 可微调裁切范围；
- OCR 很吃 CPU（约 1 秒/帧）：只想了解剧情时，用 `/kv ocr off` 或参数页关掉「OCR 画面硬字幕」，走字幕轨/语音会快很多；
- 内嵌字幕轨支持 SRT/ASS（转成 SRT 读取），但只取第一条字幕流；
- 网页桥会话关闭后消息可能发不出去，进度推送都带了超时；
- 若同时跑了多个 AstrBot 实例，只有真正持有 6199 的那个会收到 QQ 消息。
